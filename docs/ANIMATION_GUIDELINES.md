# ANIMATION GUIDELINES — правила анимаций

Проект рассчитан на **большое количество сложных анимаций**. В репозитории
установлены два взаимодополняющих инструмента; финальное распределение ролей
фиксируется в `docs/DESIGN_REFERENCE.md` (раздел 7) после исследования референса.

## Инструменты

| Инструмент                                                | Сильные стороны                                                                                                      | Когда выбирать                                                                                                  |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Motion 14** (`motion/react`)                            | Декларативный API, presence/layout-анимации, spring по умолчанию, простая интеграция с React-состоянием              | UI-переходы, hover/tap микровзаимодействия, появление/исчезновение элементов, page transitions, layout-анимации |
| **GSAP 3 + ScrollTrigger** (`gsap`, `gsap/ScrollTrigger`) | Скролл-оркестрация, pin, scrub, timelines, плагины (SplitText/DrawSVG через Club-альтернативы), точная синхронизация | Scroll reveal, stagger-сцены, параллакс, pinned sections, scrub-анимации, text/image эффекты                    |

**Правило выбора:** если эффект управляется скроллом как таймлайном — GSAP.
Если эффект — реакция на UI-состояние (hover, route, mount) — Motion.
Комбинация допустима и типична: Motion для «прикладных» переходов,
GSAP для крупный скролл-сцен. Не дублируй один и тот же эффект обоими.

## Общие технические правила

1. **Анимируем только compositor-friendly свойства:** `transform`, `opacity`,
   при необходимости `clip-path`/`filter`. Никогда — `top/left/width/height/margin`
   (layout thrashing). Для «изменения размеров» — `scale`, для движения — `translate`.
2. **`prefers-reduced-motion`:** базовый CSS-гейт уже включён в
   `src/app/globals.css`. JS-анимации обязаны проверять `matchMedia`:
   при reduced motion — либо отключать, либо заменять мгновенным состоянием.
3. **GSAP в React:**
   - только в Client Components (`"use client"`);
   - регистрация плагинов один раз на модуль: `gsap.registerPlugin(ScrollTrigger)`;
   - контекст и очистка: `gsap.context()` внутри `useEffect` (или `useGSAP`-хук),
     `revert()` в cleanup — чтобы не текуть при маршрутах App Router;
   - при динамическом контенте — `ScrollTrigger.refresh()` после загрузки.
4. **Motion в React:** компоненты `motion.*` в Client Components;
   серверная обёртка остаётся Server Component.
5. **Производительность:** тяжёлые сцены не блокируют гидратацию; GSAP-сцены —
   `next/dynamic` при необходимости; следить за количеством одновременно
   активных ScrollTrigger'ов.
6. **Stagger:** использовать единые токены длительностей/кривых из
   `src/styles/tokens.css` (`--duration-*`, `--ease-*`) — CSS-анимации и
   JS-анимации читают одни и те же значения, чтобы язык движения был консистентен.
7. **Тесты:** скролл-сцены не должны ломать e2e smoke-тесты: начальное
   состояние страницы видимо без JS-скролла.

## Чек-лист перед merge анимационной фичи

- [ ] Только transform/opacity (или обоснованное исключение)
- [ ] `prefers-reduced-motion` обработан
- [ ] Очистка GSAP-контекста/Motion-эффектов на unmount
- [ ] Нет jank на 60fps (проверка в DevTools MCP → Performance)
- [ ] Работает на mobile/tablet вьюпортах
- [ ] Фокус и клавиатурная навигация не нарушены
