# Design Reference Research — исследование референсного сайта

## Когда применять

- Перед началом реализации дизайна портфолио (обязательный этап).
- При добавлении нового референса или повторном анализе.
- НЕ применять для запуска/проверки собственного сайта (для этого есть Playwright e2e и web-gui-tester).

## Цель

Извлечь из референса **полную, воспроизводимую спецификацию** и зафиксировать её в
`docs/DESIGN_REFERENCE.md` — единственном источнике истины по дизайну проекта.

## Обязательный порядок работы

1. **Изучи существующий файл** `docs/DESIGN_REFERENCE.md` (если он уже заполнен — дополняй разделы, не перезаписывай без причины).
2. **Открой референс через Playwright MCP** (`browser_navigate`, вьюпорты 1440×900, 768×1024, 390×844).
3. **Скриншоты**: по секциям и full-page на всех трёх вьюпортах; сохраняй в `docs/research/screenshots/` с понятными именами (`<page>-<viewport>-<section>.png`).
4. **Разбери DOM и стили через Chrome DevTools MCP**:
   - computed styles ключевых элементов (шрифты, размеры, цвета, отступы);
   - межсекционные расстояния и контейнерные ширины;
   - сетки и выравнивания;
   - анимации: имена классов, CSS transitions/keyframes, библиотеки (gsap, framer-motion — по глобальным объектам и коду).
5. **Динамика**: прокрути страницу, наведи курсор, кликни интерактивные элементы, посмотри console и network (загруженные шрифты, JS-бандлы — какие библиотеки реально используются).
6. **Responsive behavior**: пройди брейкпойнты, зафиксируй, что скрывается/перестраивается (гамбургеры, сокращение текста, отключение эффектов).
7. **Заполни docs/DESIGN_REFERENCE.md** по шаблону разделов (см. структуру файла) и сослался на скриншоты.
8. **Сформулируй рекомендацию по анимационному стеку**: GSAP (+ ScrollTrigger) или Motion — на основе того, что видно в референсе (pinned sections, scroll-scrub, параллакс → GSAP; UI-микровзаимодействия, layout-анимации, presence → Motion). Допустима комбинация: Motion для UI-состояний, GSAP для скролл-сцен.

## Правила точности

- Ничего не выдумывай: каждое значение (цвет, размер, easing) — из computed styles или правдоподобной аппроксимации с пометкой «оценка».
- Извлекай реальные значения из CSS-переменных референса (`getComputedStyle` на `:root`), а не из скриншотов «на глаз».
- Шрифты — из `network` (файлы woff2) и `document.fonts`; фиксируй семейство, веса, fallback-стек.
- Пиши значения в токен-формате, готовом к переносу в `src/styles/tokens.css`.

## Ограничения

- Не копируй контент референса (тексты, картинки) — только структура, метрики и поведение.
- Не создавай компоненты во время исследования — только документация.
- Результат этапа — обновлённые `docs/DESIGN_REFERENCE.md` + скриншоты, без изменений кода дизайна.
